# Kestrel 0.8.0 Unified Integration Release

## Outcome

Ship Runtime, Protocol, SDK, Memory, adapters, CLI/TUI, Desktop, Kestrel One, internal services, documentation, and hosted infrastructure as one supported 0.8.0 release line while retaining Beta product status.

Kestrel One source remains cloneable from `v0.8.0`; only the Lumi-hosted service is invitation-only. Desktop 0.8.0 is a signed manual download and does not move stable OTA metadata from 0.7.0.

The immutable Runtime npm artifact published as 0.8.0 omitted required MCP Security runtime files, and 0.8.1 exposed an npm global-install failure through a transitive optional dependency. The corrected Runtime/CLI npm distribution is 0.8.2 with exact 0.8.0 first-party dependencies. These are packaging-only corrections; the suite, source tag, Desktop, Kestrel One, Protocol, SDK, Memory, and adapters remain 0.8.0.

## Frozen candidate rule

Freeze one integration PR-head SHA and build every candidate from it. Any update to the branch invalidates the candidate evidence. Before stable cutover, `main`, npm `latest`, production Vercel aliases, GitHub Latest, and Desktop OTA remain unchanged.

## Implementation gates

1. Enforce the root version across every workspace and exact Kestrel One dependency pin.
2. Pack and inspect all eight npm artifacts in dependency order: Protocol, Memory, Workspace Skills, SDK, Next, AI SDK, Observability, Runtime/CLI.
3. Validate package dependency resolution and clean consumers on macOS arm64 and Linux x64.
4. Validate Runtime/Protocol/API migrations, docs contracts, Kestrel One, CLI, and Desktop from the same SHA.
5. Build exact-revision Vercel previews and all five Fly roles using immutable image digests.
6. Preflight only migrations pending in the target environment.
7. Build, sign, notarize, and verify Desktop DMG/ZIP and the macOS arm64 CLI archive.
8. Run an isolated manual signed 0.7.0-to-0.8.0 Desktop upgrade and prove settings, credentials, project/session history, migrations, and Local Core identity are preserved.
9. Record all results in the machine-checked unified release evidence bundle.

## Atomic cutover

After every candidate gate passes:

1. Create annotated `v0.8.0` at the frozen SHA and a draft GitHub release with immutable artifacts.
2. Merge the integration PR with a merge commit and prove the tag tree and merged `main` tree are identical.
3. Apply pending production migrations, roll out the frozen Fly bundle, and promote the exact Kestrel One preview.
4. Run hosted canaries, then move the seven 0.8.0 packages and corrected Runtime/CLI package from `release-0.8.0` to `latest`.
5. Promote the exact docs preview, publish the GitHub release as Latest, restore normal Vercel Git settings, and run public smokes.
6. Re-fetch stable Desktop OTA metadata and prove its version and hash are unchanged.

## Failure handling

- Before cutover, stop and leave staged packages under `release-0.8.0`.
- Never unpublish 0.8.0 or replace release assets in place; fix published defects with a patch.
- Roll Vercel and Fly back to recorded immutable predecessors.
- Never reverse data migrations destructively. Roll application code back only when compatible; otherwise fix forward.
- Do not declare any individual 0.8 surface Latest while another required surface is failing.

The public release contract is documented in the [0.8 release record](../../apps/docs/content/reference/releases.mdx) and [0.7-to-0.8 upgrade guide](../../apps/docs/content/build/upgrading-to-0-8.mdx).
