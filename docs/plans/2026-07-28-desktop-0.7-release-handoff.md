# Kestrel Desktop 0.7 OTA Release Handoff

## Purpose

This document hands off the Kestrel Desktop 0.7 release recovery, packaging,
Apple signing and notarization, OTA publication, update proof, and macOS
uninstall proof.

It distinguishes work that is implemented and locally proven from work that
still requires engineering, operator approval, release credentials, public
infrastructure, or a clean Apple-silicon test Mac. It is deliberately not a
claim that Desktop 0.7 has shipped.

The release policy is:

- Desktop versions are independent from the root package, web product, and
  public protocol packages.
- The public baseline is Desktop `0.7.0`.
- The OTA proof release is Desktop `0.7.1`.
- Do not move or replace the existing root `v0.7.0` tag.
- Use Desktop-specific tags `desktop-v0.7.0` and `desktop-v0.7.1`.
- macOS arm64 is the only Desktop 0.7 target.
- The minimum supported macOS version remains macOS 13.
- Stable updates use
  `https://updates.lumicorp.ai/desktop/stable/arm64`.
- Immutable versioned objects live under
  `desktop/releases/<version>/arm64`.
- The stable `latest-mac.yml` is the only intentionally replaceable object.

## What Is Implemented

### Safe branch recovery

- Recovery started from `origin/main`.
- The macOS uninstall branch was incorporated.
- Desktop 0.7 version and selected documentation/OAuth work were ported.
- The broken WIP updater simplification was not ported.
- The raw `afterPack` dependency copy and JSON-signing workaround were not
  ported.
- Previously generated `.app`, DMG, ZIP, update metadata, and smoke evidence
  were treated as invalid.

### Portable Desktop package boundaries

- `apps/desktop-runtime` is a private workspace package with an explicit
  production dependency manifest.
- Its generated `payload/` is an allowlisted copy of runtime-owned source,
  migrations, runner and CLI entrypoints, models, agents, tools, and required
  scripts.
- The Electron shell and Local Core runtime are prepared as separate
  lockfile-backed production deployments using pnpm `9.12.2`.
- The packaged Local Core deployment is placed at
  `Contents/Resources/kestrel-runtime`.
- Runtime repository resolution points to `kestrel-runtime/payload`.
- `asar` remains disabled because runtime files and native modules are executed
  directly.
- Electron Builder is prevented from re-collecting the pnpm workspace graph.
  Prepared production `node_modules` trees are included as explicit resources.
- The release package includes the arm64 Swift uninstall helper.
- Package preflight checks cover missing production dependencies, local
  dependency paths, external or broken links, unexpected platforms, secrets
  and environment files, native architecture, embedded runtime imports, and
  the uninstall helper.

The package modes are:

```bash
# Unsigned unpacked app. This is the local proof gate.
pnpm desktop:package:dir

# Signed arm64 DMG, ZIP, blockmaps, and latest-mac.yml.
# This requires the release environment described below.
pnpm desktop:package
```

### Update, shutdown, and uninstall safety

- Update blockers are structured and preserve `source`, `code`, `message`, and
  `count` through state, preload IPC, dialogs, and diagnostics.
- Local Core shutdown requests discriminate between `uninstall` and
  `desktop_update`.
- Local Core closes admission before evaluating lifecycle state.
- A blocked request returns structured blockers and reopens admission.
- An accepted request leaves admission closed and does not cancel active work.
- Desktop has its own activity admission gate for restart-unsafe work outside
  Local Core.
- Update preparation never calls `stopDesktopProjectRun`, aborts a request, or
  cancels an execution.
- Update operations are manual: check, download, and explicit install/restart.
- Automatic download and install-on-quit remain disabled.
- The updater uses generated `app-update.yml`; it does not call
  `setFeedURL()`.
- Concurrent or reentrant updater operations are rejected.
- Stale updater events are ignored.
- Installation may be retried after a blocked state.
- Update and uninstall share the Local Core lifecycle truth and admission
  fence.

### OTA publication code

The publisher:

- derives its version from `apps/desktop/package.json`;
- validates `latest-mac.yml`;
- requires DMG, ZIP, and both blockmaps;
- verifies every updater file entry's base64 SHA-512 digest and byte size
  against local artifacts before writing any R2 object;
- requires legacy `path` and `sha512` metadata to match the corresponding file
  entry;
- streams large artifacts to R2;
- writes versioned artifacts with `If-None-Match: *`;
- verifies uploaded size and SHA-256 metadata with `HeadObject`;
- creates immutable `SHA256SUMS.txt`;
- writes immutable release metadata with public versioned URLs;
- gives artifacts a one-year immutable cache policy;
- gives channel metadata `no-cache, no-store, max-age=0`; and
- promotes channel metadata separately using `If-Match` or `If-None-Match`.

The expected default object layout is:

```text
desktop/
  releases/
    0.7.0/
      arm64/
        Kestrel-0.7.0-mac-arm64.dmg
        Kestrel-0.7.0-mac-arm64.dmg.blockmap
        Kestrel-0.7.0-mac-arm64.zip
        Kestrel-0.7.0-mac-arm64.zip.blockmap
        SHA256SUMS.txt
        latest-mac.yml
  stable/
    arm64/
      latest-mac.yml
```

## Failure and Rollback Rules

- If source or unsigned package validation fails, do not sign.
- If signing, notarization, stapling, Gatekeeper, or signed smoke fails, do not
  upload.
- If an immutable object uploads but verification fails, do not promote
  metadata.
- Never overwrite a versioned artifact with different bytes.
- Never rebuild and republish different bytes under the same Desktop version.
  Fix the defect and increment the Desktop version.
- If stable metadata has not moved, leave clients on the existing version.
- If stable metadata moved to a bad release, stop further promotion, preserve
  evidence, and use a conditional metadata update to point to a previously
  verified immutable release only after explicit approval.
- Do not delete immutable public artifacts during incident response.
- Do not delete the recovery stash until the release is complete.
