Use this playbook to move an exact candidate into production without rebuilding between verification and promotion.

## Assign operational responsibility

| Layer | Owner | Required evidence |
| --- | --- | --- |
| Application and Vercel | Auth, routes, preview, promotion | Deployment ID, revision, allowed/denied path |
| Database | Schema and data health | Pending-only preflight, backup, migration record |
| Fly and workers | Five immutable image roles and queues | Digests, rollout state, role canaries |
| Runtime and store | Sessions, events, outcomes, replay | Known-session completion and inspection |
| Providers | Registry, qualification, models, leases | Profile/model readiness and short run |
| Release owner | Gates, artifacts, decision, rollback | Signed approval and evidence index |

## Prepare an exact revision

Record `0.8.0`, commit SHA, Vercel deployment identity, package manifests, database target, worker image digests, and configuration revisions. Build all artifacts from that frozen source.

## Preflight migrations

Inspect actual current and pending migrations, compatibility, backup, and stop conditions. Apply only pending migrations; never assume every migration since a previous product version must be replayed.

## Release a change

Build a Vercel preview and immutable worker images. Validate auth, provider/profile readiness, one terminal and one streaming request, waiting/cancellation, persistence, Mission Control, artifacts, and traces before any production alias or worker rollout.

## Verify workers and canaries

Roll the five Fly roles by approved digest, check queues and health, and run role-specific canaries. A healthy HTTP service is insufficient if a worker, image, queue, or provider path is stale.

## Record evidence

Retain version/revision, deployment ID, image digests, migration state, gate results, canary correlation, approver, timestamps, and public artifact checksums. Keep credentials and private reasoning out of the record.

## Roll back or fix forward

Promote the already verified Vercel deployment rather than rebuilding it. Roll application aliases and Fly roles back to previous exact identities when migration compatibility permits. Never reverse data migrations destructively; stop and fix forward when rollback cannot preserve data contracts.

<Outcome>
  <p>The production path runs the same exact revision and immutable artifacts that passed preflight, user-path smoke tests, and canaries.</p>
</Outcome>
