Use this playbook to advance the protected `production` branch while keeping each delivery channel independently provable and recoverable.

## Assign operational responsibility

| Layer | Owner | Required evidence |
| --- | --- | --- |
| Application and Vercel | Auth, routes, native deployment | Deployment ID, revision, allowed/denied path |
| Database | Schema and data health | Ordered migrator result and compatibility evidence |
| Fly components | Catalog-owned images and private workers | Exact digests and role health |
| RunPod worker | Managed deployment processing | Exact digest and private worker health |
| Runtime and store | Sessions, events, outcomes, replay | Known-session completion and inspection |
| Providers | Registry, qualification, models, leases | Profile/model readiness and short run |
| Production owner | Protected-branch decision and rollback | Reviewed change and provider evidence |

## Advance production

Merge the reviewed replacement to `main`, then advance the protected `production` branch. Source revisions remain diagnostic metadata; production authority is the provider deployment identity or immutable image digest owned by each channel.

## Preflight migrations

Run the dedicated database job with only the unpooled production connection. Apply ordinary ordered migrations and preserve expand/deploy/contract compatibility.

## Let each channel select its work

Vercel deploys natively. Fly and RunPod select roles only from the catalog's declared inputs. A role that did not change is not rebuilt merely to manufacture a coordinated revision.

## Verify workers and Environment runtime canaries

Verify every deployed Machine's exact digest and provider-native health result. When Router or Workspace Runtime changes, update the configured Environment through its durable lifecycle, run the existing live Workspace and Preview proofs, and atomically advance the Environment Runtime Channel. Do not update the remaining fleet automatically.

## Record evidence

Retain the protected-branch revision, Vercel deployment ID, migration result, exact image digests, worker health, runtime version/channel generation, canary operation, and timestamps. Keep credentials and private reasoning out of the record.

## Roll back or fix forward

Promote the prior Vercel deployment or redeploy each Fly/RunPod application's recorded prior digest. Select the previous Environment Runtime Version only after its canary. Never reverse data migrations destructively; stop and fix forward when rollback cannot preserve data contracts.

<Outcome>
  <p>Every production channel proves and recovers its own authority, while tenant runtime defaults advance only as one canary-proven immutable pair.</p>
</Outcome>
