## Compatibility rule

Use exact `0.8.0` contracts across Runtime, Protocol, SDK, Memory, Next.js, AI SDK, Observability, Workspace Skills, and compatible clients. Install the corrected Runtime/CLI npm distribution as `@kestrel-agents/kestrel@0.8.2`; it pins its first-party dependencies to 0.8.0. Do not combine 0.7 and 0.8 contracts or add an application-side shim for removed APIs.

## Product matrix

CLI/TUI uses the Runtime package and supports Node.js 22 on macOS arm64 and Linux x64. Desktop 0.8.0 is a signed manual macOS arm64 application. Kestrel One source is tagged 0.8.0; Lumi hosting runs an exact identified deployment of that product version.

## Persistence and migrations

Desktop and Local Core preserve their owned settings, credentials, projects, sessions, and history across the 0.8 manual upgrade. Hosted operators apply only pending migrations and verify application/worker compatibility before promotion.

## Unsupported combinations

- Mixed 0.7 and 0.8 Kestrel package graphs
- Removed Board/Task or project snapshot write APIs
- Desktop 0.8.0 installed through the stable OTA pointer
- Broad approvals reused for a different action
- A hosted deployment whose actual Vercel result, Machine image tag, or tenant operation was not verified

## Historical releases

The [0.7 upgrade guide](/build/upgrading-to-0-7) remains available as history. It is not current integration guidance.

## Verify a deployed system

For hosted operation, record the Vercel deployment and migration result, the operator-selected tag and provider record for each changed Machine, the exact tenant operation when applicable, and one successful terminal result. Do not infer one target's state from another target's result.
