Start with the work in front of you. Open a project on your computer, join a shared team workspace, work from the terminal, or connect Kestrel to an application you own.

## Choose what you want to accomplish

- [Download Kestrel Desktop](/desktop/install), connect a model, and complete a task in a local project.
- [Join Kestrel One](/kestrel-one/getting-started), open a Project, and start a Thread with your team.
- [Get Kestrel One source](/kestrel-one/source-and-hosting) for inspection and local development.
- [Install the CLI/TUI](/cli/install) to work with Kestrel directly from the terminal.
- [Build your first agent](/build/building-your-first-agent) and run it from a TypeScript application.

The [journey chooser](/start/quickstart) compares those starting points in more detail.

## Understand the release model

Kestrel `0.8.0` is one coordinated version across packages, CLI/TUI, Desktop, and Kestrel One source. npm, signed Desktop downloads, source tags, and hosted invitations remain distinct distribution or access channels. A hosted deployment also records its exact revision and image identities.

## Learn the foundation when you need it

Read [What Kestrel includes](/start/why-kestrel) for the product map. Use [Core concepts](/start/concepts) for shared vocabulary, [Architecture](/start/architecture) for system boundaries, and the [Runtime model](/start/runtime-model) to trace identity, execution, recovery, memory, control, and evidence.

These docs target Kestrel `0.8.0` across the public package line, CLI/TUI, Desktop, and Kestrel One source. Installation and hosted-access channels remain distinct; check [Release status](/start/release-status) before distributing an artifact or publishing an integration.
