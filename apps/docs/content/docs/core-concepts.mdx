Kestrel uses the same small set of concepts across Desktop, Kestrel One, CLI/TUI, and SDK applications. Learn the identity and ownership of each concept before choosing an API or recovery action.

## Runtime

The Runtime advances validated turns, calls models and tools, commits visible output, and records terminal outcomes. Its effective profile also owns recovery, evaluation, budgets, memory, and telemetry policy.

## Execution Protocol

The Protocol defines request and result shapes, conversations, stream events, approvals, recovery decisions, Mission Control commands, health, and correlation. Consumers validate these contracts instead of inferring state from text.

## Local Core

Local Core is the supervised runtime bridge used by Desktop and local terminal/application workflows. It reports readiness and build identity, preserves owned state, restarts when configuration changes require it, and attempts safe self-healing when its process is unhealthy.

## Runner service

A runner service is the trusted execution boundary behind an application. Local Core serves local work; hosted runners and workers serve remote applications such as Kestrel One. Browsers never receive runner or provider credentials.

## Run and terminal outcome

A run is one execution attempt. It finishes as completed, failed, or cancelled, or remains waiting for an exact request. Human-facing `assistantText`, structured finalized data, runtime status, and operator affordances remain separate.

## Agent

An Agent combines a profile with application-owned instructions and integration behavior. The effective profile and provider registry determine model, capability, tool, recovery, memory, evaluation, and budget policy.

## Session

A Session is the durable local conversation identity used by Desktop, CLI/TUI, and SDK clients. Follow-up turns, waits, recovery choices, events, and terminal outcomes remain attached to it.

## Thread and Project

A Kestrel One Thread is the durable shared conversation. A Project groups Threads with members, revisioned context, Knowledge, Apps, an Environment, and Mission Control work.

## Workspace

A local Workspace is the owned folder or checkout where tools operate. A Kestrel One Environment is the hosted compute and capability boundary. A Project is the collaboration boundary and may select an Environment.

## Stream, subscription, and replay

Streams deliver live events, subscriptions deliver durable background activity, and cursors resume ordered history. Replay reconstructs persisted decisions and evidence without silently repeating uncertain external effects.

## Operator control

Operator control inspects or steers running and waiting conversations. Decisions bind to the exact pending request, actor, session/thread, and current state.

## Profile and Provider Registry

A Profile selects registered runtime policy. A Provider Registry entry identifies a provider/model path and its qualified capabilities. Configured, reachable, compatible, qualified, and authorized are separate states.

## Mission Control

Mission Control owns project work, attempts, evidence, review, and acceptance. It is not transcript metadata or the legacy Board/Task system.

## Memory and Knowledge

Runtime Memory stores authorized facts with subject, issuer, provenance, and query policy. Kestrel One Knowledge supplies organization or Project documents through revisioned context. Conversation history remains a third, separate continuity source.

## Recovery Decision

A Recovery Decision selects one registered action for observed unhealthy state. Its option identifier binds to the exact pending request; it is not a free-form retry instruction.

## Approval and External Effect

An external approval grants one authorized actor permission for one exact action/effect. Changes to target, parameters, actor, or Environment require a new validation and possibly a new grant.

## Budget

A Budget governs spend. Durable allocations reserve, commit, release, and reconcile value with idempotent evidence.

## Build Identity

Build Identity combines product version with exact source revision and deployment artifacts. Hosted evidence also includes migrations, workers, and immutable image digests.
