<GuideNote step="Step 1" title="Use the shipped Kestrel profile">
This tutorial sends one request to the canonical `kestrel` profile and agent.
</GuideNote>

By the end of this tutorial, a Node.js script will send a request to Kestrel and
read its terminal result. The script uses `kestrel web`, the authenticated
loopback HTTP bridge to Local Core.

## Before you start

You need Node.js 22, a configured local Kestrel installation, and a provider/model that satisfies the canonical profile's required capabilities. Run:

```bash
kestrel setup --profile kestrel
kestrel web
```

`kestrel web` prints `KESTREL_RUNNER_SERVICE_URL` and
`KESTREL_RUNNER_SERVICE_TOKEN`. Export those values in the terminal that will
run the script. Keep the token in server-side code.

The profile ID used by the SDK is `kestrel`. Kestrel owns the runtime policy;
applications do not invent alternate profile or agent identities.

## Install the SDK

```bash
pnpm add @kestrel-agents/sdk@0.8.5
pnpm add -D tsx
```

## Create and run the agent

Create `scripts/kestrel-agent-smoke.ts`:

```ts
import { createAgent } from "@kestrel-agents/sdk";

const agent = createAgent({
  id: "kestrel-agent",
  profileId: "kestrel",
  target: {
    kind: "remote",
    baseUrl: process.env.KESTREL_RUNNER_SERVICE_URL!,
    authToken: process.env.KESTREL_RUNNER_SERVICE_TOKEN!,
  },
});

const context = {
  actor: {
    actorId: "user-123",
    actorType: "end_user" as const,
    displayName: "Taylor Example",
    tenantId: "acme",
  },
  tenantId: "acme",
};

const terminal = await agent.run(
  {
    sessionId: "kestrel-session-001",
    message: "Summarize the current project and identify the next useful task.",
  },
  context,
);

console.log(terminal.type);
console.log(terminal.payload.result.assistantText);
await agent.close();
```

Run it from the project directory:

```bash
pnpm exec tsx scripts/kestrel-agent-smoke.ts
```

`kind: "remote"` selects HTTP because the script is using the loopback bridge.
The bridge forwards the request to Local Core, which remains responsible for
execution and durable state. An explicit local SDK target instead uses Local
Core's Unix socket and token.

## Read the terminal result

`terminal.type` identifies whether the run completed, failed, was cancelled, or
is waiting. For a completed run, `terminal.payload.result.assistantText` is the
canonical text to show a person. Structured application data remains in
`terminal.payload.result.output`.

Reuse `kestrel-session-001` for a follow-up that belongs to the same
conversation. Choose a new session ID for unrelated work.

If the prior result is waiting, resume its exact pending request instead of starting a replacement run. Verify the follow-up retains the same session identity while receiving a new request and run correlation.
